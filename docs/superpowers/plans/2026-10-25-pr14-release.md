# PR14 owner release implementation plan

Goal: one owner-run sudo entrypoint, no production actions during development.
Spec: the user's release requirements and docs/upgrade.md executable code anchor.
Architecture: shell bootstrap, standalone Python owner-maintenance transaction,
root-private journal/report and standalone crash recovery. Reuse BackupManager,
ReleaseManager switching/restarts, audit verification and runtime sealing.
Normal signed upgrade checks remain unchanged. This is the separately reviewed
offline root procedure, not a signature bypass in autonomous releases.

## Constraints and decisions

- Exact candidate 3e9a2f4 and documented artifact hashes; no build/network install.
- Only main.py/mcp.py change in the application package. No migration/grants,
  credentials, systemd definitions or stable recovery-runtime replacement.
- Root TTY confirmation is mandatory even though development is preauthorized.
- Missing owner session/host verification inputs fail before installation.
- No CLI/environment option permits production checks to be disabled.
- Crash rollback restores previous executable AND protected anchors. Locking
  prevents a late watchdog from reverting a completed transaction.
- Test adapters exist in tests, never as a selectable production backend.

Hostile symlinks/ancestors; TOCTOU of reviewed artifacts; termination between
anchor writes/codeswitch; watchdog/parent races; expired auth and durable jobs;
secrets in error output; resumed or unrelated existing armed journals.
